## Contexte

Décision D2 = A (2 champs engagement + paiement). DatePicker impose :
- `date` (engagement) toujours obligatoire
- `date_paiement` obligatoire UNIQUEMENT si statut = 'payée'/'justifiée'
- `date_paiement` désactivée si statut = 'annulée'

## Constats

### Composant créé : `src/components/ui/DatePicker.tsx` (~120 lignes)

API : mode, value, onChange, label, engagementDate, paymentDate,
onEngagementChange, onPaymentChange, status, engagementLabel, paymentLabel,
error, disabled, className.

Modes :
- `single` : un input date avec label
- `engagement-payment` : 2 inputs (engagement toujours requis, payment selon statut)

Règles métier :
- `status ∈ ['payée', 'justifiée', 'payee', 'justifiee']` → paymentDate requise (border-danger si vide)
- `status ∈ ['brouillon', 'en_attente', 'validée']` → paymentDate optionnelle
- `status ∈ ['annulée', 'annulee']` → paymentDate désactivée

Style cohérent avec FormInput (border-default/danger, focus:ring-accent-primary).
Warnings visuels uniquement, pas de blocage de soumission.

### Test créé : `src/components/ui/DatePicker.test.tsx` (4 tests)
1. Mode single : label + input, onChange appelé
2. Mode engagement-payment : 2 inputs affichés
3. Statut payée + paymentDate vide : border-danger
4. Statut en_attente : pas de border-danger
